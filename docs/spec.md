# VocalAlignTune 開発仕様書（v0.1 — CLIプロトタイプ）

## 概要

MIDIノートをガイドとして、ボーカルWAVの**タイミング**と**ピッチ**を一括自動補正するオフライン処理ツールを開発する。
Revoice Proの自動アライメント、Voviousのピッチ処理品質を参考にしつつ、両者の弱点（誤検知の多さ、手作業の煩雑さ）を解消することが目的。

- 第1段階：Python CLI（WAV + MIDI 入力 → 補正済みWAV 出力）
- 第2段階（将来）：C++でプラグイン化。**ARA2は対応しない**。**JUCEは使用しない**（GPL/商用ライセンス・スプラッシュ表示の制約のため）
- ライセンス方針：**コピーレフト（GPL等）およびクレジット表示義務のある依存を全面的に禁止**。許容はMIT / BSD / ISC / zlib系のみ
- 本仕様書は第1段階のみを対象とする

## 前提条件（ユーザー確定事項）

1. **MIDIとWAVは頭出し済み**（先頭が一致している）。オフセット自動検出は不要
2. **MIDI側にノートが無い区間は処理しない**（タイミングもピッチも一切触らずスルー出力）
3. **WAV側に一定音量以上の音声が無い区間は処理しない**（RMS閾値、デフォルト -45 dBFS、CLIオプションで変更可）
4. テンポ情報はMIDIファイルから取得（可変テンポ対応）

## 最重要品質要件：ピッチ補正の音質

「素直に実装するとガビガビになる」問題への対策。Voviousの公式説明から得られた設計指針：

- Voviousは時間領域の細分化再合成（PSOLA系）ではなく**FFTによる周波数領域処理**で位相ズレ・倍音歪みを抑制している
- **ニューラルネットによるフォルマント分析**でピッチ変化にフォルマントを自然追従させ、ヘリウムボイス化を防いでいる
- ピッチ検出もニューラルネットベース

これを踏まえた本ツールの設計原則：

### P1. シフトエンジンは周波数領域＋フォルマント保持

- **第一候補：Signalsmith Stretch**（MITライセンス、C++、周波数領域、位相コヒーレンス処理、フォルマント補正対応、タイムストレッチとピッチシフトを同一エンジンで実行可能）
  - Pythonバインディングが存在するか確認し（PyPIの `python-stretch` 等）、無ければpybind11で薄いラッパーを書く
- **比較・フォールバック：WORLD（pyworld）**（F0/スペクトル包絡/非周期性に分解 → F0のみ差し替えて再合成。フォルマント＝スペクトル包絡が構造的に保持される）
  - WORLDはブレス成分がビジーになる既知の癖があるため、A/B比較用として実装し `--engine {stretch,world}` で切替可能にする
- ❌ 使用禁止：librosa.effects.pitch_shift（単純STFT位相ボコーダ、位相ロック無しでガビつく）、単純リサンプリング

### P2. 無声音・ブレスはピッチシフトしない

- ガビつきの主因は無声子音（サ行・タ行等）とブレスへのシフト適用
- 有声/無声判定（ピッチ検出器の信頼度 + ZCR/スペクトル特徴）を行い、**無声フレームはシフト比1.0で素通し**
- 有声⇔無声の境界は短いクロスフェード（5〜20ms）で繋ぐ

### P3. ノートに「スナップ」しない補正カーブ

- ノート区間ごとに検出F0の**中央値**とMIDIノート音高の差分（セント）を求め、その**オフセットのみ**を補正する
- ビブラート・しゃくり・微細な揺らぎは差分に含めず保持する（＝Melodyneのドリフト補正相当の考え方）
- 補正量カーブは時間方向に平滑化（例：ガウシアン、σ=30〜50ms）し、ノート境界で急峻なジャンプを作らない
- しゃくり保持オプション：ノート先頭 N ms（デフォルト80ms）は補正強度をランプインさせる
- 補正強度パラメータ `--pitch-strength 0.0〜1.0`（デフォルト0.85）で「完全一致」ではなく自然さを優先できるようにする

### P4. ピッチ検出はニューラル系

- **第一候補：RMVPE**（歌声向け高精度、既存の学習済みモデルを利用）
- フォールバック：torchcrepe、さらに軽量環境向けにpYIN（librosa）
- `--detector {rmvpe,crepe,pyin}` で切替

## タイミング補正の設計

Revoice Proの誤検知原因（片側にしか無い音、細切れ素材、レガートでエネルギー手掛かり不足）を構造的に回避する。

### T1. 無音ベースのセクション分割（誤検知対策の核）

1. WAVをVAD/RMSゲートでフレーズ単位に分割（無音 ≥ 200ms を区切りとする。閾値・最小無音長はオプション化）
2. MIDI側も同様に、ノート間ギャップ ≥ 200ms でフレーズ分割
3. フレーズ同士を時間順に対応付け（頭出し済み前提なので、開始時刻の近さで貪欲マッチングで十分。対応の取れないフレーズは**未処理でスルー**し、ログに警告出力）

### T2. フレーズ内のノート単位アライメント

1. フレーズ内で、検出したオンセット候補（母音開始点）をMIDIノートオンセットに対応付ける
   - 母音開始点の検出：有声化開始点（voicing onset）を主手掛かりにする。**波形先頭（子音）ではなく母音頭を拍に合わせる**のが原則
   - ノート数とオンセット数が一致しない場合はDTW（特徴量：F0＋エネルギー＋有声フラグ）で対応付け、信頼度が低いノートは移動しない
2. 各対応点のタイムワープマップを構築し、Signalsmith Stretchの可変レートストレッチで適用
3. 子音は直前の母音に付随して一緒に移動する（子音・母音間を切断しない）
4. 最大移動量ガード：`--max-shift-ms`（デフォルト120ms）を超える移動が必要な箇所は補正せず警告（誤検出の可能性が高いため）

### T3. 処理順序

**タイミング補正 → ピッチ再検出 → ピッチ補正** の順で行う（タイムワープ後にF0マップがずれるため、ピッチはワープ後の音声で検出し直す）。

## 非処理ルール（確定仕様）

| 条件 | 挙動 |
|---|---|
| MIDIノートが無い区間 | タイミング・ピッチとも未処理で素通し |
| WAV側RMSが閾値未満の区間 | 未処理で素通し（デフォルト -45 dBFS） |
| フレーズ対応が取れない | 未処理＋警告ログ |
| 移動量が max-shift 超過 | 未処理＋警告ログ |
| ピッチ検出信頼度が低いフレーム | ピッチ補正をスキップ（シフト比1.0） |

「迷ったら触らない」を全体原則とする。誤補正よりも未補正のほうが復旧コストが低い。

## CLI仕様

```
vat process input.wav guide.mid -o output.wav \
  [--engine stretch|world] \
  [--detector rmvpe|crepe|pyin] \
  [--pitch-strength 0.85] \
  [--timing-strength 1.0] \
  [--max-shift-ms 120] \
  [--silence-thresh-db -45] \
  [--min-gap-ms 200] \
  [--attack-preserve-ms 80] \
  [--report report.json] \
  [--pitch-only | --timing-only]
```

- `--report`：各ノートの補正前後F0、移動量、スキップ理由をJSONで出力（デバッグと信頼構築のため必須実装）
- 進捗表示とフレーズごとの処理ログを標準出力に出す

## 技術スタック

- Python 3.11+
- mido または pretty_midi（MIDI解析、可変テンポ対応のため pretty_midi 推奨）
- numpy / scipy / soundfile
- Signalsmith Stretch（バインディング or pybind11ラッパー）
- pyworld（比較エンジン）
- RMVPE学習済みモデル（torch）、フォールバックに torchcrepe / librosa(pYIN)
- Silero VAD または RMSベース自作ゲート（依存を減らすならRMS自作で開始）

## テスト・検証計画

1. **合成テスト**：正解が既知のテストデータを自動生成する
   - クリーンな歌声（またはサイン波＋フォルマントフィルタの擬似ボーカル）に、既知のピッチずれ（±30セント）とタイミングずれ（±80ms）を人工的に加え、補正後の残差を数値評価
   - 合格基準：ピッチ残差 中央値 < 10セント、タイミング残差 中央値 < 20ms
2. **ヌルテスト**：ずれの無い入力を処理した際、出力が入力とほぼ同一であること（非処理ルールの検証）
3. **音質検査**：処理前後のスペクトログラム比較画像を自動出力（`--report` に含める）。無声子音区間の波形が変化していないことを確認
4. 実素材でのリスニングテストはユーザーが実施

## ガイドアダプタ（MIDI / WAVガイドの抽象化）

ガイド入力を内部表現（ノート列＋任意でF0カーブ）に正規化する層を設け、下流の補正処理を共通化する。

- **MIDIガイド**：ノート列をそのまま内部表現へ（従来仕様）
- **WAVガイド**（Synthesizer V等の合成ボーカルを想定）：
  1. ガイドWAVをF0検出（本番と同じ検出器）＋無音分割
  2. F0の安定区間をノート化（中央値音高・開始/終了時刻）して擬似ノート列を生成
  3. タイミング対応付けの特徴量は**F0カーブ＋有声/無声フラグ**を主とする（音色・エネルギー依存のマッチングは行わない。SynthVと生声の音色差による誤検知を構造的に回避するため）
  4. ピッチターゲットは2モード：
     - `note`：擬似ノートの中央値音高に対するオフセット補正（MIDIガイドと同じ挙動）
     - `curve`：ガイドのF0カーブ自体を転写（ビブラート・しゃくりの移植。転写強度 `--pitch-strength` に従う）
- ガイドWAVにも非処理ルールを適用（無音・低信頼度区間はノート化しない）

CLI追加：

```
vat process input.wav guide.wav -o output.wav --guide-type wav --pitch-target note|curve
```

（`--guide-type` は拡張子から自動判別をデフォルトとする）

## マイルストーン

1. **M1**:MIDI/WAV読み込み、フレーズ分割、非処理ルール、レポート出力（音声加工なしのドライラン）
2. **M2**:ピッチ補正のみ（`--pitch-only`）を両エンジンで実装、合成テストで品質確認 ←ここが山場
3. **M3**:タイミング補正（ノート単位アライメント＋可変ストレッチ）
4. **M4**:統合（タイミング→ピッチの順次処理）、パラメータ調整、ドキュメント
5. **M5**:ガイドアダプタのWAV対応（擬似ノート化＋`curve`モード）。検証はSynthVガイド＋実録ボーカルのペアで行う

## 将来拡張（今は実装しない）

- プラグイン化：**iPlug2（zlib系ライセンス、クレジット不要）を採用**。出力形式はVST3＋CLAP（必要に応じAU）。JUCEは使用しない
  - **VST3 SDKは3.8（2025年10月）以降MITライセンス**。旧来のSteinberg契約手続きは廃止済みで、著作権表示・ライセンス文の保持のみで商用利用可。VSTロゴ使用は任意（使わなければ商標規約も不適用）
  - ニューラルピッチ検出はtorch依存のため、C++移植時は**ONNX Runtime（MIT）**での推論に置き換える。M2の時点で検出モデルをONNXエクスポート可能な形で扱っておくこと
- 歌詞テキスト＋強制アライメントによる音素レベルの母音頭検出（日本語対応）
- 複数Dubトラックの一括処理（Revoice代替ユースケース）
- フォルマントのニューラル追従（Vovious相当。まずはSignalsmith/WORLDの包絡保持で十分か検証してから判断）
