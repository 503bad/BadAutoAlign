# 06. スタンドアローンGUI版

Electron + Pythonサブプロセス（`vat serve`）。UI/UX原案は ../soan.md。
補正処理はCLIと完全共通で、GUIは可視化と人間の介入だけを担う。

## 1. 画面構成

- 4レーン: **ガイドボーカル / 補正対象ボーカル / 補正結果 / オケ（任意）**。
  オケは再生専用（処理には使わない）
- 各レーン左側の操作パネル: トラック名・**音量ロータリーノブ**
  （上下ドラッグ/ホイール、ダブルクリックで100%、聴感二乗カーブ）・
  **ミュートMボタン**。いずれも再生中にリアルタイム反映（GainNode常設）
- WAVはレーンへのドラッグ&ドロップで読み込み
- ヘッダ: 補正ボタン（タイミング/ピッチ/両方）、pitch strength・max shift・
  スクラブ長の数値入力、**再補正**、**保存**、再生

## 2. 表示（波形・ズーム）

- 波形は多段min/maxピラミッドからの**仮想化描画**（表示窓のみ描画）。
  ピンチ（ctrl+ホイール）/alt+ホイールでカーソル位置基準ズーム
  （フィット〜2000px/s）、ホイール/横スワイプでパン
- 波形クリックでプレイヘッド移動。再生はミュートされていない全レーンの同時再生

## 3. マーカーの意味論（残差主導の3状態＋手動）

**表示の軸は「何をしたか」ではなく「何を操作すべきか」**（02 §6）。
ノートごとに:

| 表示 | 状態 | 意味 | ユーザーの行動 |
|---|---|---|---|
| グレー細線 | ok | 合っている（補正済み含む）。\|残差\|<40ms | 不要 |
| 黄＋残差ms表示 | off | まだズレが残っている（例「+80ms」） | ドラッグ/ピン留め→再補正 |
| 赤点線 | unknown/unmatched | 自動では判断できない（対応なし or 計測不能） | 聴いて確認。必要ならマーカー作成 |
| 青 | manual | 手動アンカー | 再補正で反映 |

- ガイド⇔ボーカル間に対応ライン（ok状態は淡く、要注意状態は濃く）
- ホバーで平易な日本語ツールチップ（「+62ms動かして合わせ済み」
  「まだ+80msズレています — ドラッグで合わせて再補正」等）
- 凡例はフッターに常時表示。補正完了時に「要確認 N箇所（黄x/赤y）」を表示し、
  **黄と赤を潰していけば完成に近づく**作業リストとして機能させる

## 4. マーカー操作

- **長押し試聴**: ガイド側・ボーカル側ともマーカーを押している間だけ
  その位置から再生。**ミュート・音量ノブをバイパス**して等倍で直結
  （フェード付き、離すと停止）
- **ドラッグ**（ボーカル側）: 3px以上動かすと試聴からドラッグへ移行。
  ドラッグ中は**スクラブ再生**（既定80ms、UIで40〜200ms可変、フェード付き、
  断片長の75%間隔でスロットル）と元位置からのオフセットms表示。
  離すと手動アンカー {src=新位置, dst=ガイド芯} として確定
- **ダブルクリック**: ボーカル側=ピン留め（位置そのまま、ガード無視で完全適用。
  「あと80msズレ」への最短の直し方）。ガイド側の赤（対応なし）=ボーカル側に
  マーカーを生成してドラッグ可能にする
- **再補正**: 手動アンカー一式を付けて再処理（manual_anchors → 05 §3）。
  手動アンカーはガード免除・最優先（02 §7）

## 5. アーキテクチャ / パッケージング方針

- main.js がPythonを `uv --directory <repo> run vat serve` で起動
  （配布時は環境変数 VAT_SERVE_CMD で同梱Pythonに差し替え）。
  行区切りJSONで要求/応答、stderrの処理ログをパースして
  **実進捗のプログレスバー**（フレーズN/M、全画面オーバーレイ）を表示
- 保存: Electronの保存ダイアログで補正結果WAVを書き出し
  （既定: 元ボーカルと同フォルダ、`<元名>_corrected.wav`）
- Windows配布（未実装・方針）: (1) wrapper.cpp をCMakeでプリビルドし
  DLL同梱＋ローダーに同梱優先分岐、(2) Python embeddable + wheels同梱
  または PyInstaller で `vat serve` を単一exe化、(3) electron-builder
