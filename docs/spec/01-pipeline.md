# 01. 処理パイプライン

## 全体の流れ

```
入力WAV ─┬─ フレーズ分割（RMSゲート）
ガイド ──┴─ ガイドアダプタ（MIDI→ノート列 / WAV→F0検出→擬似ノート化）
              │
              ▼
        ノート⇔フレーズの対応付け（時間オーバーラップ）
              │
   ┌──────────┴（フレーズごとに独立処理）──────────┐
   │ 1. ピッチ検出（フレーズ切り出し音声）           │
   │ 2. タイミング補正（→ 02-theory-timing.md）      │
   │ 3. ピッチ再検出（ワープ後の音声で検出し直す）    │
   │ 4. ピッチ補正（→ 03-theory-pitch.md）           │
   │ 5. クロスフェード付きスプライス（出力へ書き戻し）│
   └──────────────────────────────────────────────┘
              │
              ▼
        出力WAV + レポートJSON
```

処理順序が「タイミング → 再検出 → ピッチ」なのは、タイムワープ後は
F0マップの時刻がずれるため。ピッチ補正はワープ後の音声で検出し直した
F0に対して行う。

## ガイドアダプタ

ガイド入力を内部表現（ノート列 + 任意でF0カーブ + ガイド音声）へ正規化し、
下流を共通化する。

- **MIDIガイド**: pretty_midiでテンポマップを解決し秒単位のノート列へ。
  重なり（レガート打ち込み）は後ノート開始で前ノートを切る
- **WAVガイド**: F0検出（本番と同一検出器）→ 有声区間を切り出し、
  ピッチ跳躍（>0.8半音）でさらに分割 → 各区間の中央値音高で擬似ノート化。
  無音・低信頼度区間はノート化しない（非処理ルールの適用）。
  ガイド音声そのものも保持し、タイミング補正の音響アライメントに使う
- ガイドWAVのF0解析はファイル実体＋解析パラメータをキーに
  ディスクキャッシュされる（2回目以降は即時）

## フレーズ分割と対応付け

### 分割（T1）

- ボーカル: フレームRMS（中帯域ではなく全帯域）が閾値（既定 -45dBFS）以上の
  区間を活性とみなし、無音が min_gap（既定200ms）以上続いたら区切る。
  各フレーズは前後の無音へ max_shift+50ms のマージンを広げて切り出す
  （ワープでノートを動かす余地。隣接フレーズとは重ねない）
- ガイド: ノート間ギャップ ≥ min_gap でノート列をグループ化

### 対応付け

ガイドとボーカルで**フレーズ粒度は一致しない**（合成ガイドは息継ぎが短く
長い連続フレーズになりがち）。そのためフレーズ同士の1対1対応ではなく、
**ノート単位で「最もよく重なるボーカルフレーズ」に割り当てる**。

- ノートの半分（最大100ms）以上重ならないノートは「対応する音声なし」として
  スルー（警告ログ＋レポート記録）
- ノートが割り当てられなかったフレーズは未処理で素通し

## 非処理ルール（確定仕様）

| 条件 | 挙動 |
|---|---|
| ガイドノートが無い区間 | タイミング・ピッチとも未処理で素通し（ビット一致） |
| ボーカルRMSが閾値未満の区間 | 未処理で素通し |
| ノートに対応する音声が無い | 未処理＋警告（no_matching_phrase / 対応音声なし） |
| フレーズ内でワープもピッチ補正も不要 | フレーズごと素通し（再合成させない） |
| 各種ガードに該当（→02, 03） | 該当ノート/区間のみ未補正＋理由をレポート |

「フレーズ内でワープが恒等写像・ピッチ補正カーブが閾値未満」の場合は
エンジンを通さないため、**ずれの無い入力は出力が入力とビット一致**する
（ヌルテストの保証。エンジンの再合成劣化を持ち込まない）。

## スプライス

処理したフレーズは10msのクロスフェードで出力バッファへ書き戻す。
フレーズ境界は無音（ゲート以下）にあるため、フェードによる劣化は実質ない。
