# 02. タイミング補正の理論

本文書が仕様書の中核。最終設計だけでなく、**棄却した方式とその理由**を含めて記す。
この分野の設計は「何が失敗するか」の知見にこそ価値があるため。

## 1. 問題定義

ボーカル x(t) とガイド g(t) は同じ歌詞・同じ旋律を歌っており、頭出し済み。
求めたいのは単調増加の時刻写像 w: src→dst で、x(w⁻¹(t)) が知覚的に g(t) と
同期して聞こえるもの。制約:

- フレーズ境界（無音）で恒等（フレーズ全長は不変、未処理区間はビット一致）
- 局所テンポ歪み（dw/dt の 1 からの乖離）は可聴劣化になるため小さく保つ
- 誤補正よりも未補正（原則1）

## 2. 棄却した方式とその理由（負の知見）

### 2.1 ノート単位アンカー（オンセット↔ノートの個別対応）

最初の実装。ボーカルの有声化開始点をガイドのノート開始に個別に対応付け、
各対応点をアンカーとしてワープした。2つの致命的問題が実素材で発生:

1. **掛け違い（off-by-one対応）**: F0と有声フラグだけの対応付けは、同じ高さの
   連続音節や細切れのノートで1音節ズレた対応を作る。誤アンカーは音を
   まるごと隣の音節の位置へ動かすため、破壊的
2. **計測ジッタがそのまま音になる**: 短いノートが密集するレガート区間では、
   アンカー計測（芯検出）自体に±50〜100msのノイズがあり、隣接ノートに
   +99ms→-110msのような物理的にあり得ない交互シフトが適用され「ガタつき」になる。
   **歌声は連続体であり、隣接ノートのズレが交互に±100ms振れることはない**——
   この事実が後の平滑カーブ方式の根拠になった

### 2.2 フレームDTW（F0＋有声フラグ / 音響特徴）

フレーズ全体をフレーム単位でDTWし、パスからノート位置を写像する方式。
CMVN正規化MFCC＋Δ（話者非依存の音素特徴）＋ピッチクラス＋有声フラグまで
特徴を強化すると異常値（±1500ms級）は消えたが、**パスの「にじみ」**は残った。
DTWは1音節が複数ノートへ連続的に流れることを妨げないため、長い持続や
息継ぎで対応が滑り、ノート単位の精密なアンカーには不向き。

### 2.3 ギャップスライド（セグメント丸ごとリジッド移動）

無音ギャップで区切られたセグメントを伸縮なしで移動する方式（人間のエディタの
カット＆スライド相当）。合成テストでは機能するが、実素材で
**繰り返しフレーズ問題**に直面した: ポピュラー音楽は同型の楽節を繰り返すため、
±1拍分（170BPMなら8分音符=176ms）ズレた位置に、包絡もピッチも高相関の
「偽の一致」が存在する。包絡相関・ピッチ照合をすり抜けて1音節分の掛け違い
スライドが発生した。ピーク優位性検定（次点候補と僅差なら棄却）と
セグメント内均一性検定（前半後半のラグ一致）を課すと誤爆はゼロになるが、
同時に実素材で有効なスライドもゼロになった。**局所的な音響情報だけでは
繰り返しの曖昧性は原理的に解消できない**。実装はフラグ付きで履歴に保存
（コミット70bb920）、既定経路からは除外。

## 3. 対応付け: 音節単位の離散アライメント

対応付け（どの音がどのノートか）とラグ推定（どれだけずれているか）を分離し、
対応付けには**順序保存の離散アライメント**を使う。

- ボーカルを音節（モーラ）単位に分割（→ 04-detection.md）。
  日本語歌唱の「1ノート ≒ 1モーラ」構造を仮定
- ガイドノート列と音節列を Needleman-Wunsch 型DP（挿入/欠落ペナルティ付き）で
  対応付け。コスト = ピッチクラス差（オクターブ非依存）＋ 位置差
  （頭出し前提の事前分布。近い候補を弱く優先=「迷ったら動かさない方向」）＋
  長さ比 ＋ 母音特徴距離（ガイド音声がある場合。CMVN-MFCC重心）
- フレームDTWと違い**1音節=1ノートの構造制約を強制**でき、音数が一致すれば
  先頭からの1:1対応に自然に収束する。数が合わなければ明示的に挿入/欠落となる
- 結果は対応表（AlignmentEntry: 判定 matched / low_confidence / note_skipped、
  コスト）としてレポートに出力し、GUIの表示とレビューの基礎データとする

対応付けの結果はアンカー計測（ノートごとのズレの測定）とレポートに使うが、
**最終的なワープの駆動には使わない**（§5）。個別計測はジッタが大きい（§2.1）ため、
証拠の一つに格下げするのが本設計の要点。

## 4. 芯（P-center）: 何を「合っている」と定義するか

物理的な発声開始と知覚的な頭は一致しない。音声学ではこれを
**P-center（perceptual center）**、音楽音では **PAT（perceptual attack time）** と呼ぶ。

- 非打楽器的な立ち上がり（歌声を含む）ではPATは物理オンセットより
  平均+23〜51ms遅く、人間同士でも±40ms程度ばらつく（Polfreman, ISMIR 2013）
- P-centerの音響相関は「振幅包絡の最速上昇点」が有力だが、日本語では
  当てはまりが弱く**母音開始の知覚的先読み**が示唆される（Rathcke+ 2024, JASA）

本ツールでの帰結:

1. **アンカーの定義は両側対称に**。ボーカル側だけ有声化開始点（しゃくり・
   ガナリの起点）を使い、ガイド側はF0安定開始点を使う——という非対称は、
   しゃくり分の**系統的な後ろズレ**を生む（実測で確認）。
   芯の推定（ピッチ到達点と中帯域エネルギー最速上昇点の遅い方）を
   **ガイドとボーカルに同じ検出器で**適用し、検出器バイアスを相殺する
2. ただし最終的なラグ推定の主役は包絡相互相関（§5）であり、これは
   「エネルギーパターン同士の最良一致」という意味で対称なP-center照合の
   連続版になっている。ユーザーがDAWの波形比較で見る「合っている」と
   同じ定義を最適化することになり、検証もこの定義で行う

参考文献: Marcus 1981（P-center位置の線形則）/ Scott 1998（中帯域エネルギー
急上昇）/ Harsin 1997（心理音響包絡の変化率）/ Villing 2010（モデル網羅レビュー）/
Gordon 1987（楽音PAT）/ Polfreman ISMIR 2013 / Rathcke+ JASA 2024。

## 5. ラグ推定: 包絡相互相関の平滑カーブ（最終方式）

### 5.1 ラグのサンプリング

中帯域(300–3000Hz)エネルギー包絡（dB、σ≈15ms平滑）同士の局所相互相関で、
フレーズ内を0.2秒刻みにラグを標本化する:

- 各時刻tでボーカル包絡の窓 [t−0.4s, t+0.4s] をガイド包絡に対し
  ±max_shift の範囲でスライドし、正規化相関が最大のズレを採る
- ゲート: 窓内の包絡の起伏 < 6dB（無音・平坦）、または最大相関 < 0.6 の
  サンプルは捨てる（**ラグが定義できない場所では測らない**）

ノート単位の芯計測よりはるかにノイズが少なく、レガートでも密に取れる。
VocALign / Revoice系と同じ原理。サンプルが取れない場合（ガイド音声なし等）は
ノートアンカー計測にフォールバックする。

### 5.2 頑健平滑化

サンプル列 {(tᵢ, lagᵢ, 信頼度wᵢ)} から滑らかなラグカーブ lag(t) を推定:

1. **加重メディアン局所回帰**: 0.25秒グリッド上で、±0.8秒窓のサンプルの
   加重（信頼度×距離重み）メディアン
2. **外れ値除去→再推定**: カーブから80ms以上離れたサンプルを捨てて一度だけ再フィット
3. **クリップ**: |lag| ≤ max_shift（既定120ms）
4. **傾き制限**: 隣接グリッド間のラグ変化 ≤ 25%（局所テンポ歪みの上限）
5. **不感帯**: |lag| < min_shift×0.8（≈28ms）の区間はゼロ（恒等写像）に落とす。
   フレーズの一部だけがずれている場合に、合っている区間へカーブの微小ノイズが
   乗るのを防ぐ（「合っている所は触らない」の曲線版）
6. **閉ループ検証**: カーブの各グリッド点で「lag(t)だけ動かすと包絡相関が
   実際に margin(0.03) 以上改善する」ことを確認し、改善しない点はゼロに落とす。
   大きなミスマッチ（ガード対象）の近傍でサンプルが汚染され、
   カーブが良好な隣接区間を引きずる事故への最終防衛線
7. 遷移をガウシアン(σ≈0.15s)でなだらかに接続
8. カーブ全体が min_shift 未満なら**ワープ自体を行わない**（ヌルテスト保証）

### 5.3 ワープの適用

カーブを区分線形アンカー列に変換し（フレーズ両端は恒等で固定）、
Signalsmith Stretch のストリーミングAPIで可変レートストレッチする。
アンカー整形（_sanitize_anchors）で単調増加と伸縮率 [0.25, 4.0] を強制。
出力長はフレーズ長と厳密に一致させる。

### 5.4 ガード一覧

| ガード | 既定値 | 目的 |
|---|---|---|
| max_shift | 120ms | これ超の移動は誤対応の可能性が高い（クリップ/棄却） |
| min_shift | 35ms | 検出量子化・ジッタより小さい移動はしない |
| 相関ゲート | r ≥ 0.6 | ラグが定義できない場所で測らない |
| 起伏ゲート | ≥ 6dB | 同上（無音・平坦窓） |
| 傾き制限 | 25% | 局所テンポ歪みの上限 |
| 不感帯 | 28ms | 合っている区間を触らない |
| 閉ループ検証 | +0.03 | 動かして良くならないなら動かさない |
| アンカーピッチ照合 | 100セント(折返し) | 掛け違い対応の棄却（ノート計測側） |
| 一貫性 | 0.8s内120ms | 隣接アンカーの矛盾棄却（フォールバック経路） |

## 6. 残差の定義とレポート

- **計測ラグ**（§5.1の生サンプル）と**適用ラグ**（最終ワープ）を両方レポートに出力
- ノートごとに applied_ms（その位置で実際に動かした量）と
  residual_ms（計測 − 適用 = まだ残っているズレ）を算出。
  近傍に信頼できる計測が無いノートは residual = 不明とする
- GUIはこの残差を主役に「合っている / まだズレ(量つき) / 判断不能」の
  3状態を表示する（→ 06-gui.md）。**表示の軸は「何をしたか」ではなく
  「何を操作すべきか」**

## 7. 手動アンカー（人間との分業）

§2で示したとおり、構造的な歌い回しの違い・繰り返しの曖昧性は自動では
解決できない。GUIからの手動アンカー {src, dst, note_index} は:

- **全ガードを免除**され、最優先で適用される（近傍±max(0.3s, 3×移動量) の
  自動アンカーを退けてから挿入）
- 単調性の整形のみ通常どおり適用
- レポート上 manual=true として区別される

これにより「自動で95%＋要確認箇所を人間が確定」のループが成立する。

## 8. 既知の限界

- **区間内でズレ量が流動するケース**（例: +290ms→+151msと変化して直後に反転）は、
  傾き制限つきの滑らかなワープでは追従できず、追従させると§2.1のガタつきが
  再発する。歌い直しか手動編集の領域
- 繰り返しフレーズの±1拍ズレは局所情報では判別不能（§2.3）
- 頭出しの全体オフセットは補正対象外（前提条件）。ズレている場合は
  フレーズごとの基準シフトが部分的に吸収するが、入力段で合わせるのが正
