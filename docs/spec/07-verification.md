# 07. 検証

## 1. 検証の考え方

- **合成テスト**: 正解既知の擬似ボーカル（帯域制限ノコギリ波＋2共振フォルマント
  フィルタ＋ビブラート＋エンベロープ）に既知のずれを与え、補正後残差を数値評価。
  pytestに常備し、全変更でリグレッションを検出する
- **実素材評価**: SynthVガイド＋実録ボーカル（約3分）で、
  **ガイドとの局所ラグ**（中帯域包絡の窓相互相関、±250ms探索）を
  楽曲全体にサンプリングし、補正前後で比較する。単一の数字ではなく
  分布（中央値・50ms超の箇所数・悪化点数）で判断する
- リスニングテストはユーザーが実施し、指摘箇所をレポート
  （対応表・lag_profile）と突き合わせて原因を特定する

## 3. 実素材での実測結果（開発時点の記録）

対象: 187.76秒・44.1kHz、SynthVガイド（擬似ノート389個）＋実録ボーカル。

### タイミング（ガイドとの局所ラグ、73サンプル点）

| 指標 | 補正前 | 補正後 |
|---|---|---|
| \|ラグ\|中央値 | 34.8ms | **23.2ms** |
| 50ms超の箇所 | 28点 | 25点 |
| 補正で悪化した点（>+15ms） | — | 1点 |

方式変遷の効果（同素材）: ノート個別アンカー期はシフト計測が最大±1563msまで
暴れ、適用アンカーの隣接矛盾（掛け違いの兆候）が7件 → 平滑カーブ＋各種検証の
最終形で異常値消滅・矛盾ほぼ0。残る50ms超は大半がガードによる意図的未補正
（構造的な歌い回しの違い）。

### ピッチ（フレームレベル、ガイド両有声フレーム）

補正前: 残差中央値50セント / ±50セント以内率 52.5%
→ 補正後: **30セント / 64.4%**（strength=0.85、揺らぎ保存のため0にはならない）。

### 性能

全パイプライン約36〜40秒（初回はガイド解析込みで約60秒、以後キャッシュ）。
テストスイート22件・約30秒。

## 4. 既知の限界（実素材で確認済みの具体例）

- 区間内でラグが流動するケース（+290→+151msの後に-174msへ反転など）は
  自動補正の対象外として残る。当該素材では2〜3箇所。手動アンカーで解決可能
- 繰り返しフレーズの±1拍（8分音符）ズレは局所情報で判別不能（02 §2.3）
- 検出系の量子化（hop=11.6ms）により、±1〜2グリッド（12〜23ms）の残差は
  計測上のノイズフロアであり、聴感上の問題とは限らない

## 5. デバッグの定石

1. ユーザーから問題の時刻をもらう
2. report.json の該当フレーズの alignment / lag_profile / notes を確認
3. 局所ラグ計測（out/配下の評価スクリプト）で補正前後の実挙動を数値化
4. 「計測が悪いのか・判断が悪いのか・適用が悪いのか」を切り分けてから直す。
   表示上の指標（マーカー等）と実波形の挙動を混同しない
