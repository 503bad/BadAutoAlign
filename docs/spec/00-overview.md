# 00. システム概要

## 目的

ガイド（Synthesizer V等で作った手本ボーカルのWAV、またはMIDIノート列）を基準として、
実録ボーカルWAVの**タイミング**と**ピッチ**をオフラインで一括自動補正する。
Revoice Proの自動アライメントとVovious系のピッチ処理品質を参考にしつつ、
両者の弱点（誤検知の多さ・手作業の煩雑さ）を構造的に回避することを目指す。

## 構成

```
┌─ CLI ──────────────┐   ┌─ スタンドアローンGUI (Electron) ─┐
│ vat process        │   │ 3トラック表示 / マーカー編集       │
└──────┬─────────────┘   └──────┬──────────────────────────┘
       │                        │ JSON-RPC (stdio) ← vat serve
       ▼                        ▼
┌──────────────────────────────────────────────┐
│ Python コア (src/vat/)                        │
│  ガイドアダプタ → フレーズ分割 → 対応付け      │
│  → タイミング補正 → ピッチ再検出 → ピッチ補正  │
└──────────────────────────────────────────────┘
```

- 補正処理は完全に共通（CLIとGUIで同一パイプライン）
- シフト/ストレッチエンジンは Signalsmith Stretch（自作C ABIラッパー、
  固定シードで決定的）。比較用に WORLD

## 設計原則

### 原則1: 迷ったら触らない

誤補正よりも未補正のほうが復旧コストが低い。全段に通底する原則で、
具体的には以下として現れる（詳細は各文書）:

- 非処理ルール（ノート無し区間・無音区間・対応不能フレーズは素通し）
- 各種ガード（最大移動量・最小移動量・信頼度・ピッチ照合・一貫性）
- **閉ループ検証**: 「動かすと実際に一致が良くなる」ことを確認してから動かす
- 未処理区間は入力と**ビット一致**（再合成を通さない）

### 原則2: 検証は数値で

処理前後のガイドとの局所ラグ・ピッチ残差を実測し、改善が数値で示せない
変更は採用しない。合成テスト（正解既知）＋実素材の局所ラグ計測を常備する
（→ 07-verification.md）。

### 原則3: 自動化の限界を明示し、人間に引き継ぐ

局所的な音響情報だけでは原理的に判別できないケース（歌い回しの構造的な違い、
繰り返しフレーズの曖昧性）が存在する。これらは無理に自動化せず、
GUIで「要確認」として明示し、手動アンカー（ガード免除の確定指定）で
人間が解決する分業とする（→ 02 §7, 06）。

### 原則4: ライセンス

コピーレフト（GPL等）およびクレジット表示義務のある依存を全面禁止。
許容は MIT / BSD / ISC / zlib 系のみ。現行構成は購入ゼロで商用配布可能
（→ ../commercial-licenses.md）。

## 前提条件（確定事項）

1. ガイドとボーカルは**頭出し済み**（先頭一致）。全体オフセットの自動検出は行わない
2. ガイドにノートが無い区間は処理しない
3. ボーカルのRMSが閾値未満（既定 -45 dBFS）の区間は処理しない
4. MIDIガイドのテンポはMIDIファイルから取得（可変テンポ対応）
5. サンプルレートはガイド・ボーカルで一致していること（実用上44.1/48kHz）

## 用語

| 用語 | 意味 |
|---|---|
| ガイド | 手本となる音源（SynthV等のWAV、またはMIDI） |
| 擬似ノート | WAVガイドのF0安定区間から生成したノート列 |
| フレーズ | 無音（既定200ms以上）で区切られた歌唱区間 |
| 音節（モーラ） | 補正の対応付け単位。日本語の1ノート≒1モーラ構造を仮定 |
| 芯（P-center） | 発声の知覚的な頭。物理的な発声開始とは異なる（→ 02 §4） |
| ラグ | ある時刻でのボーカルのガイドに対する時間ズレ。正=ガイドより早い（後ろへ動かすべき） |
| アンカー | ワープマップの制御点 (src, dst)。srcの音をdstへ動かす |
