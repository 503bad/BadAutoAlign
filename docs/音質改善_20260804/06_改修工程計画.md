# 06. 改修工程計画

方針（05）を4フェーズに分割する。各フェーズは単独でリリース可能な単位とし、
フェーズ末に評価（07 の指標＋聴取）を通過してから次へ進む。
「迷ったら触らない」原則（pipeline.py 冒頭）は全フェーズで維持する。

## Phase 0: 評価基盤の整備（先行・必須）

改善は測れなければ判定できない。実装に着手する前に評価を固める。

| # | タスク | 対象 | 完了条件 |
|---|---|---|---|
| 0-1 | テストコーパス作成 | `tests/corpus/` | 歌声＋ガイド 5〜10 ペア（レガート/子音多め/ビブラート/かすれを含む）。権利上同梱可能なもの |
| 0-2 | 客観指標スクリプト | `tools/eval_quality.py` | 07 の指標（F0-RMSE、LSD、transient 指標、ヌルテスト残差）を JSON 出力 |
| 0-3 | A/B 試聴キット | `tools/ab_render.py` | 補正区間の before/after/参照を切り出して並べた wav 群を自動生成 |
| 0-4 | ベースライン計測 | docs | 現行 main の指標値を記録（改修の比較基準） |

工数目安: 2〜3日

## Phase 1: 即効改修 — バリバリ音の主因除去とフォルマント保持

**目標: 「バリバリ」の解消と声質変化の解消。体感品質の大半をここで回収する。**

| # | タスク | 対象 | 内容 / 完了条件 |
|---|---|---|---|
| 1-1 | time_warp ストリーム修正 | `engines.py` | チャンク512化・入力欠落分岐除去・フレーズ累積丸め（05 §1.2）。ヌルテスト（恒等ワープ）で残差 -60dBFS 以下 |
| 1-2 | 伸縮再配分パス | `timing.py` | セグメントラベル→重み付きレート配分→PCHIP 平滑（05 §1.1）。子音・芯±40ms 上で rate 1.0±0.02 |
| 1-3 | 伸縮率ガード変更 | `timing.py` | 有音区間 0.7〜1.5 / 無音 0.25〜4.0。超過時は無音吸収へ再配分、不能なら未補正＋警告 |
| 1-4 | フォルマント保持 | `engines.py` `native/wrapper.cpp` | `set_formant_factor(1.0)`＋`setFormantBase`（要 API 追加確認）。母音 /a/ の ±3半音シフトでフォルマント周波数変化が聴感上判別不能 |
| 1-5 | tonality limit | `engines.py` `config.py` | `tonality_limit_hz=8000`。子音・ブレスの高域質感が原音同等 |
| 1-6 | 設定フラグ | `config.py` `cli.py` | `formant_preserve` / `tonality_limit_hz` / `elastic_warp`（新旧切替、既定 on） |
| 1-7 | 評価・チューニング | - | Phase 0 指標がベースライン比: transient 指標改善、F0-RMSE 同等以上、聴取で「バリバリ」消失 |

工数目安: 1〜1.5週

## Phase 2: 補正カーブの高度化と1パス統合

**目標: 「補正されている感」の低減。Melodyne 的な自然さへ。**

| # | タスク | 対象 | 内容 / 完了条件 |
|---|---|---|---|
| 2-1 | ドリフト補正 | `pitch.py` | 2Hz ゼロ位相ローパス誤差の加算補正（05 §4.1）。ビブラート振幅の変化 <5% |
| 2-2 | 遷移同期 | `pitch.py` | ノート境界遷移を \|dF0/dt\| 最大点に同期した raised-cosine へ（05 §4.2） |
| 2-3 | 非線形吸着 | `pitch.py` `config.py` | 小ズレ全補正・大ズレ部分補正の g 関数（05 §4.3） |
| 2-4 | 1パス統合 | `engines.py` `pipeline.py` | ワープ＋トランスポーズ同時適用（05 §3）。フラグで2パスへ戻せること。処理時間 ~40% 減 |
| 2-5 | 評価 | - | ABX で Phase1 比の改善有意、ヌルテスト維持 |

工数目安: 1〜1.5週

## リスクと退避

| リスク | 退避策 |
|---|---|
| 再配分パスで移動量の等価性が崩れる | 芯位置の到達誤差を assert（±5ms）。超過時は旧マップへフォールバック |
| formant_base 追加で wrapper ABI 変更 | ソースハッシュで自動再ビルド（native/__init__.py 既存機構）。プリビルト DLL の再配布を packaging/ 手順に追記 |
| 1パス統合の品質退行 | `--two-pass` フラグで従来動作を維持 |
| RMVPE モデル配布サイズ | 初回ダウンロード方式＋pYIN フォールバック |
