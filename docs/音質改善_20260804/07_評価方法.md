# 07. 評価方法 — 「良くなった」を測る

音質改善は主観に流れやすい。本プロジェクトでは客観指標＋構造化した聴取評価＋
回帰テストの3本立てで判定する。すべて Phase 0 で整備する（06 参照）。

## 1. 客観指標（tools/eval_quality.py）

### 1.1 ヌルテスト（回帰・必須）

- **恒等処理残差**: ワープマップ恒等・補正カーブ0で処理した出力と原音の差分 RMS。
  目標: **-60 dBFS 以下**（エンジンを通しても劣化しないことの保証）。
  現行 min_shift_ms / min_correction_cents の「触らない」設計の検証でもある。
- **非補正区間残差**: 補正が適用されなかったフレーズ・区間が bit 一致（または -80dBFS 以下）。

### 1.2 タイミング補正の品質

- **transient smearing 指標**: 補正前後の子音区間（無声区間±20ms）について
  スペクトルフラックスのピーク鋭度（ピーク値 / 周辺 50ms 平均）を比較。
  比が 1.0 に近いほど滲みが少ない。
- **レート統計**: 適用ワープの局所レートのヒストグラム。有音区間で 0.9〜1.1 に
  収まる割合（目標 >95%）。
- **到達精度**: 芯アンカーの到達誤差（±5ms 以内）。改修で品質を上げても
  「合わせる」という機能が退行していないことの確認。
- **クリック検出**: 出力波形の一階差分の外れ値（>6σ）カウント。バリバリ＝
  局所的な波形不連続の直接検出。

### 1.3 ピッチ補正の品質

- **F0-RMSE / 補正達成度**: 出力を再検出し、ターゲット（ノート/ガイドカーブ）との
  誤差。改修前後で同等以上であること。
- **ビブラート保存**: 4〜7Hz 帯域の F0 変調振幅の入出力比（目標 0.95〜1.05）。
- **LSD (Log-Spectral Distance)**: シフト量ゼロ近傍の区間で入出力のスペクトル距離。
  フォルマント保持の有効性は、±3半音シフト時の **フォルマント周波数追跡**
  （LPC ルーツや praat 系推定で F1/F2 を測り、シフト前後の変化率 <3%）で確認。
- **HNR / スペクトル平坦度の変化**: buzzy 化・phasiness 化の proxy。

### 1.4 実行系

- 処理時間（フレーズ毎・全体）、ピークメモリ。1パス統合（05 §3）の効果測定。

## 2. 聴取評価（tools/ab_render.py）

- **素材**: Phase 0 コーパス（レガート/子音多発/ビブラート/かすれ声/大きなズレを含む）。
- **切り出し**: report.json の `timing_applied` / `applied_cents` から補正箇所を抽出し、
  {原音 / 現行版 / 改修版 / (あればMelodyne等の参照)} を同一区間で並べた比較 wav を自動生成。
- **方式**: ABX または MUSHRA 簡易版（隠れ参照付き 5 段階）。評価軸を分ける:
  1. バリバリ・クリック感（タイミング補正部）
  2. 子音の明瞭さ
  3. 声質の変化（フォルマント）
  4. 補正の「機械っぽさ」（ケロり・ロボ声感）
  5. 総合自然さ
- **判定**: フェーズゲートは「軸1〜3 で現行版に劣る素材がない」かつ
  「総合で過半数の素材が改善」。

## 3. 回帰テスト（CI）

- ヌルテスト（1.1）を pytest 化し、エンジン変更のたびに自動実行。
- コーパス 1 ペアのスモーク処理で指標 JSON を生成し、
  ベースライン JSON との乖離（F0-RMSE +10% 以上悪化等）で fail。
- report.json のスキーマ互換（timing_applied 等のフィールド）維持の確認。

## 4. ベースラインの記録

Phase 0 完了時に、現行 main で全指標を計測し
`docs/音質改善_20260804/baseline_YYYYMMDD.json` として保存する。
以後の全フェーズはこのファイルとの差分で語る。
