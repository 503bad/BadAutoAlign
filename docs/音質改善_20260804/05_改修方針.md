# 05. 改修方針 — 採用技術と設計変更（優先度付き）

01 の原因分析（A〜J）に対する具体策。優先度は「体感品質の改善量 ÷ 実装コスト」順。

## 1. 【P0】タイミング補正: 伸縮の再配置とトランジェント保護（原因 A・B）

### 1.1 ワープマップの「レート配分」再設計（timing.py）

ワープマップ構築の最終段に **elasticity 再配分パス** を追加する。
アンカー（芯の対応点）はそのまま制約として使い、区間内のレート配分を変える。

```
入力: 現行の WarpMap（芯アンカー列）
     + 音節区間 (syllables.py) + 有声区間 (PitchTrack.voiced) + 無音区間
処理:
  1. フレーズを [無音 | 子音(無声) | 母音アタック | 母音持続] にラベル分け
  2. 各セグメントに伸縮許容重みを付与:
       無音: 1.0 / 母音持続: 0.5 / 子音: 0.05 / アタック(芯±40ms): 0.0
  3. アンカー制約を満たすレートカーブを、重みに比例した配分で解く
     （重み付き最小二乗: min Σ (rate_i - 1)^2 / w_i、制約 Σ rate·dt = 移動量）
  4. レートカーブを PCHIP でC1連続化し、細かい折れ点列（10ms 格子）の
     WarpMap に落とす
出力: 同じ芯対応・同じ端点を持つが、レートが滑らかで
      子音・アタック上では rate≒1.0 の WarpMap
```

- 既存の `_smooth_lag_curve` / `_sanitize_anchors` はそのまま生き、後段に1関数追加する形。
- `_sanitize_anchors` の伸縮率ガードを 0.25〜4.0 → **0.7〜1.5**（無音区間は 0.25〜4.0 のまま）
  に狭める。吸収は無音へ逃がす。

### 1.2 time_warp のストリーム駆動改善（engines.py、原因 C）

- チャンク長を max 2048 → **512** に縮小し、レート階段を 10ms 粒度へ。
- `ls <= 0 or ld <= 0` の分岐を「入力は必ず送る（出力要求 0 で送る）」に変更し、
  入力サンプル欠落をなくす。
- 出力要求数は区間内累積でなく**フレーズ全体の累積**で丸め、区間境界での誤差リセットをなくす。

### 1.3 （効果不足時の追加策）HPSS ハイブリッド

1.1〜1.2 で不十分な場合のみ: librosa HPSS で調波/打撃を分離し、
調波→Signalsmith、打撃→OLA（小フレーム）で個別に伸縮して合算（02 §1.4）。
評価（07）で子音明瞭度が基準未達の場合に発動する保険。

## 2. 【P0】ピッチシフト: フォルマント保持と tonality limit（原因 F・G）

### 2.1 wrapper.cpp / native API

- `vs_set_formant_factor(handle, factor, compensate)` は既存バインド。
  wrapper.cpp 側で `setFormantFactor` / `setFormantBase` を正しく呼んでいるか確認し、
  必要なら `vs_set_formant_base(handle, freq)` を追加する。

### 2.2 SignalsmithEngine.pitch_shift（engines.py）

```python
s = StretchStream(sr)
s.set_formant_factor(1.0, compensate=True)   # フォルマント固定
# チャンクループ内:
s.set_transpose_factor(2**(semi/12), tonality_limit=8000.0 / sr)
```

- フレーズの中央値 F0 を `setFormantBase` に渡し包絡推定を安定化。
- config に `formant_preserve: bool = True` / `tonality_limit_hz: float = 8000.0` を追加。
- WORLD エンジンは構造上フォルマント保持済みのため変更不要。

## 3. 【P1】1パス統合（タイミング＋ピッチ同時適用、原因 D 軽減）

現行: time_warp（STFT 1回目）→ 再検出 → pitch_shift（STFT 2回目）。
改修: ピッチ補正カーブを**ワープ後時間軸へ写像**して、ワープと同一ストリームで適用する。

- `WarpMap.dst_to_src` で出力時刻→入力時刻を引けるため、
  補正カーブ（入力時間軸）を出力時間軸に再標本化するのは 1 行の `np.interp`。
- ワープ後の再検出は「補正量の再計測」のためだったが、オフセット補正は時間軸に不変なので
  ワープ前検出のカーブで問題ない（curve モードのみ再標本化に注意）。
- 効果: STFT 分析合成が 1 回になり、劣化・処理時間・レイテンシがほぼ半減。
- リスク: ワープとトランスポーズの同時大変更時の品質。A/B 評価で確認し、
  問題があればフラグで従来 2 パスへ戻せるようにする。

## 4. 【P1】補正カーブの高度化（原因 H）

1. **ドリフト補正**: ノート内誤差カーブ（検出 − ターゲット）を 2Hz ローパスした成分を
   オフセットに加算して補正（ビブラート帯域 4〜7Hz は通過させない急峻な IIR/FIR。
   ゼロ位相 filtfilt）。config: `drift_correction: float = 1.0`（0で現行動作）。
2. **遷移同期**: ノート境界の補正量遷移を、|dF0/dt| 最大点に中心を合わせた
   raised-cosine 遷移（幅は検出遷移幅、下限 40ms）に置換。
   現行のガウシアン平滑はフォールバックとして残す。
3. **非線形吸着**: `applied = offset * strength * g(|offset|)`、
   g は 30 cent 以下→1.0、300 cent→0.7 に漸減する単調関数。
4. attack_preserve_ms は現行維持（Melodyne 的アタック保護と同義）。

## 5. 【P2】検出の底上げ（原因 J）

- RMVPE を既定検出器化（モデル同梱 or 初回ダウンロード）。pYIN はフォールバック。
- 検出後処理: ピッチクラス整合によるサブハーモニクス/オクターブ飛び棄却、
  Viterbi 平滑（遷移コスト = 半音距離）。

## 6. 【P2】チャンク粒度・その他の微修正（原因 I ほか）

- pitch_shift のトランスポーズ更新を hop=512 のまま維持しつつ、
  カーブ側の平滑 σ 下限を dt の 2 倍以上に保証（急峻カーブでの階段防止）。
- `_splice` のクロスフェード 10ms → 境界が有声区間に落ちる場合は
  最寄りのゼロクロス／無音へスナップ。

## 7. 【P3〜/研究】ニューラル系（Vovious 方向）

- 選択肢: (a) 補正後音声の拡散モデルによる restoration（アーティファクト除去）、
  (b) DDSP 再合成（F0・ラウドネス・MFCC 条件付け）、(c) SVC 系声質保存シフト。
- いずれも配布サイズ・GPU 依存・ライセンス（学習データ）の検討が必要。
  本工程では**評価パイプライン（07）で品質天井を測るための試作**までを範囲とする。
